# Repository conventions

This is the team RL branch for a fact verifier. Read `README.md` for the directory and document map, then `verifier/TODO.md` for current priorities.

## Directory roles

- `core/` has shared reward definitions and interfaces. `retrieval/` builds and queries the FEVER index. `agent/` has the search/verify loop, controller scaffold and the demo's event-stream server (`agent/server.py`). `utils/` has data preparation and shared experiment helpers. Do not recreate a `src/` wrapper.
- `verifier/model.py` contains reusable verifier inference, prompting and scoring logic. `verifier/evaluation/` contains the shared evaluator, single-condition Slurm entry point and `results/`. The root `run.sbatch` launches the current split follow-up: evaluation of the continued 1,200-row SFT adapter and native-thinking CoT GRPO from the 5,895-row and disjoint 4,695-row SFT adapters. The completed six-condition Base/SFT × direct/CoT sweep remains saved under `verifier/evaluation/results/`. Archived claim-level predictions are in `verifier/evaluation/results/archive/`; new outputs go under `results/<condition>/<run>/`.
- `verifier/data/train/` contains committed SFT/GRPO examples; `verifier/data/eval/` has frozen claim IDs. Raw FEVER and the BM25/SQLite index must be downloaded or built locally; follow `verifier/docs/data.md`.
- Each training configuration lives under `verifier/experiments/<config>/` and each attempt under `runs/<run>/`. Submit `verifier/experiments/run_train.sbatch` for SoC training; `TRAIN_SCRIPT` selects a configuration. `OUTPUT_ROOT` can move the experiments root to another shared filesystem. Keep metadata, checkpoint files and logs under `runs/<run>/artifacts/`. Model weights and terminal `.log` files are ignored. Use a new run name; never overwrite an existing run.
- Name training configurations with lowercase hyphens in this order: `<method>-<output>-from-<start>-<model>[-<setting>]-<count>-samples`. Examples: `sft-direct-from-base-qwen3p5-2b-5895-samples` and `grpo-cot-from-sft4695-qwen3p5-2b-no-calibration-kl0-1200-samples`. The final count is the training-set size; `from-sft4695` identifies the starting adapter's SFT size. `pool1200` denotes a larger pre-filter pool; `pilot300` is the teacher-request count while the final `227-samples` records accepted rows. `kl004` means KL beta 0.04. Keep historical metadata values unchanged when moving a run directory.
- The fixed 4,695/1,200 FEVER split is documented by `verifier/data/train/sft/fever-oracle-disjoint-4695/split_manifest.json`; verify it with `python -m utils.build_disjoint_sft_grpo_split --check`. The two SFT jobs have completed on SoC according to the user. The root `run.sbatch` now evaluates the 1,200-row SFT continuation and trains native-thinking CoT GRPO from each SFT checkpoint; it uses the renamed checkpoint paths. The CoT GRPO reward uses the existing verdict-harm, evidence and invalid-format terms, with confidence calibration disabled. Keep `verifier/experiments/submit_split_comparison.sh` for a fresh four-job comparison, but do not rerun it for this comparison. Keep the fixed 1,200-row second-stage set identical in both arms.
- `verifier/docs/` records methods and historical results. `verifier/TODO.md` tracks unfinished work. `verifier/INSIGHT.md` is local and Git-ignored; do not commit it or treat it as a shared source.

## Editing and running

- Run Python modules from the repository root with `python -m ...` where a module is available. Keep Slurm submission commands rooted here. `EVAL_CONDITION` names an evaluation condition and its results folder; `RESULTS_ROOT` moves the evaluation results root while retaining condition/run subdirectories; `RESULT_DIR` selects one exact new run directory. Set only one of the two path overrides. Inspect the current SoC partition and resource limits before submitting.
- Preserve historical `meta.json` values and prediction rows as records of the original run. Update current code and documentation paths rather than rewriting their provenance.
- Name evaluation result conditions with lowercase hyphens: `<model>-<prompt>-cap<output-tokens>`. Use `baseline` for the untrained model, `sft` for this SFT checkpoint, and `cot-long` / `cot-brief` in result paths. The internal prompt-style IDs remain `cot_chain` / `cot_brief`. Historical directories were renamed for consistency; preserve their prediction rows, original logs, job IDs and commit IDs. Manifests record original names and the inferred 160/512-token caps.
- Compare experiments with the same claim IDs, model, retrieval condition and evaluator. Record seed, revision, resources, predictions, metrics and logs for each run.
- Update `README.md`, `verifier/TODO.md` and relevant `verifier/docs/` pages when commands, layout or experiment assumptions change.
- Do not commit raw datasets, indexes, checkpoints, credentials or terminal logs. Do not push or submit cluster jobs unless the user requests it.
